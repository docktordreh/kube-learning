#+title: cka-labs: CKA, CKAD and CKS practice labs and mock exams

* Overview

=cka-labs= is a local command-line training tool for Kubernetes administrators.
It creates disposable clusters, introduces a fault, checks the live cluster
state, and stores practice results in SQLite.

The project is independent of the Linux Foundation. Its labs are original
practice exercises, not certification exam questions.

Each certification has its own curriculum file in
=src/cka_labs/data/curricula/=, holding its version, domain weights and
objectives. CKA and CKAD target Kubernetes =v1.37=. CKS follows the newest
published CKS curriculum, =v1.34=. One lab can count toward several
certifications. CKA is the default; choose another one with =--cert= or
=CKA_CERT=. See [[file:docs/curriculum.org][curriculum]].

* Start with kind

Requirements: Python 3.12 or newer, Docker, and internet access for the first
install. The kind node image supports amd64 and arm64.

#+begin_src sh
uv sync
uv run cka setup
uv run cka doctor
uv run cka lab list
uv run cka lab start
#+end_src

The last command selects a lab based on your recorded results. To choose one
yourself, run =cka lab start networking-001=.

* Work through a lab

#+begin_src sh
cka lab status
cka shell
cka lab hint
cka lab check
cka lab solution
cka lab reset
cka lab stop
#+end_src

=cka shell= opens a shell with the lab's kubeconfig. =cka lab solution= is
learning mode and marks the attempt as non-clean.

The CLI keeps kubeconfigs under
=${XDG_DATA_HOME:-~/.local/share}/cka-labs/kubeconfig=. It does not read or
write =~/.kube/config=. Before it mutates a cluster, it checks the cka marker
ConfigMap in =kube-system=.

* Labs and progress

The catalog contains 22 labs across the five CKA domains. All 22 passed the
real kind conformance cycle on Kubernetes v1.37. The cycle checks setup, the
initial fault, the reference fix, grading, reset, and cleanup.

#+begin_src sh
cka practice --weakest
cka practice --domain troubleshooting
cka practice --difficulty advanced
cka practice --cert ckad
cka lab list --cert cks
cka progress
cka progress --cert ckad
cka progress networking-003
cka progress --json > progress.json
#+end_src

* Mock exam

#+begin_src sh
cka exam start
cka exam start --cert ckad
cka exam status
cka exam task 3
cka exam skip 3
cka exam submit
cka exam results
#+end_src

The default exam has eight tasks and a 120-minute limit. It splits the tasks
over the certification's domains by their official weights (CKA: 2/1/2/1/2)
and assigns points by difficulty. Kind exams use namespace-isolated tasks in one cluster. Node and
control-plane tasks are available as labs and require the kubeadm backend.

Scores measure local practice performance. They are not official certification results.

* Backends

** kind

kind runs Kubernetes nodes in Docker containers. The nodes include systemd,
kubelet, containerd, static Pod manifests, and NetworkPolicy support. Use kind
for API, workload, networking, storage, and application troubleshooting labs.
It cannot reproduce a separate kernel, VM disk, or package-level upgrade.

** kubeadm and libvirt

The kubeadm backend uses three Ubuntu VMs through Vagrant and libvirt. It
installs containerd, kubeadm, kubelet, Calico, and the node troubleshooting
tools. The backend copies the existing =cka/= Vagrant inputs into the cka data
directory and changes the network to =192.168.251.0/24=. It does not adopt the
hand-managed VMs in =cka/=.

#+begin_src sh
CKA_BACKEND=kubeadm cka lab start troubleshooting-007
#+end_src

See [[file:docs/installation.org][installation]] and [[file:docs/safety.org][safety]] before using the VM backend.
