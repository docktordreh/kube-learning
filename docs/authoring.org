#+title: Adding a lab safely

* Directory contract

Create =labs/<cert>/<domain>/<name>-NNN/= with:

| file             | audience / purpose                        |
|------------------+-------------------------------------------|
| =lab.yaml=       | typed metadata, setup, checks, hints, owner|
| =task.md=        | student-facing request only               |
| =solution.sh=    | hidden reference solution                 |
| =explanation.md= | hidden debrief and production recognition |
| =manifests/=     | declarative fixture inputs                |

=objectives= lists ids of the form =<cert>/<domain>/<key>= from
=src/cka_labs/data/curricula/<cert>.yaml=. The first objective is the primary
one: it decides the lab's directory, and the lab counts toward that domain in
exams. List an objective of another certification only when the lab really
practises it. A lab counts toward each certification it has an objective in.

The schema is strict Pydantic. Template strings use ={{name}}= and are chosen
from =params= with a persisted seed. Unknown names are errors. =captured.*=
values are recorded after setup and are available only to checks.

* State model

Declare =namespace= isolation for ordinary labs and list every owned namespace.
Declare =cluster= isolation for node/control-plane disruption. List every
cluster-scoped resource explicitly as =kind/name= in =owned=. Setup must be
idempotent after cleanup.

Checks have two roles:

- =goal=: must fail immediately after setup and pass after the student fix.
- =guard=: must pass immediately after setup and remain true, catching
  collateral changes or a security-policy weakening.

A lab that needs a pinned tool or a shared cluster component lists it in
=requires=: =helm= (the binary from =cka setup=) or a component from
=toolchain.yaml= such as =traefik=. Components are installed once per cluster
before the lab's setup. They never belong to a lab; do not list their
namespaces. Setup scripts can copy files shipped with the lab (for example a
chart) from ={{lab.dir}}= into ={{workdir}}=.

Prefer =service_endpoints=, =pods_ready=, traffic, RBAC
SubjectAccessReviews, and mounted-file behavior over comparing submitted YAML.
A valid alternative solution must receive full credit.

* Authoring loop

1. Read the official objective and an existing lab in the same domain.
2. Write the task in operational language. State constraints and the test
   entry point, not the answer.
3. Make the setup inject one reproducible, genuine fault.
4. Write a reference solution that uses normal kubectl/Linux commands and does
   not depend on an agent-only helper.
5. Add at least three progressive hints: resource, diagnostic command,
   behavior/root cause.
6. Add an explanation covering controller behavior, production symptoms, and
   valid alternatives.
7. Run the gates:

#+begin_src sh
uv run cka dev validate
uv run cka dev verify <domain>-NNN --backend kind --seed 1
#+end_src

The conformance report is the completion criterion. It must show intended
failure, reference pass, reset restoration, and scoped cleanup. If a lab needs
VM/kernel/control-plane operations, use =backends: [kubeadm]= or both and do
not fake that behavior in kind.

* authoring a public scenario scenario

=cka dev scenario-source= turns one scenario directory into a draft lab. It
reads files only and executes nothing.

#+begin_src sh
cka dev scenario-source path/to/repo/NetworkPolicy-DNS \
    -o ckad/networking/network-policies -o cks/cluster-setup/network-policies
#+end_src

The first =-o= objective decides the directory. By default the draft goes to
=<data dir>/drafts/<cert>/<domain>/<cert>-<domain>-NNN/=; use =--out= to pick
another catalog root.

What the draft contains:

- the setup scripts as one host =script= step that starts in =$CKA_WORKDIR=;
  if a script touches the node (=systemctl=, =crictl=, =/etc/kubernetes=,
  =ssh= ...), it becomes a =node= step on the control plane and the lab is
  cluster-isolated;
- every =verify.sh= as a =script= goal check, run with the read-only grader;
- the namespaces the setup creates (plus =--namespace=) as lab-owned, with
  their creation rewritten so it does not re-apply the namespace and drop the
  =cka-labs.io/lab= label. Namespaces the setup only uses, such as
  =ingress-nginx=, are not owned, so cleanup never deletes them;
- =task.md= from the intro and step texts without =<details>= blocks and
  /Solution/ sections; =solution.sh= from the code blocks of those blocks;
- a =source= entry (URL, path, commit, license) and =license notice=.

Only MIT, Apache-2.0, BSD and CC-BY-4.0 content can be authored. =--private=
allows other content for local use. Its output must stay outside every git
repository, and =cka dev validate= rejects it.

Finish a draft:

1. Read the setup and check scripts before running anything. Host scripts run
   as you, node scripts as root on a cluster node.
2. Act on the printed warnings: images outside the offline set, =/root= paths,
   verify scripts that change state (the grader is read-only), node access.
3. Replace every =TODO= marker. Write hints, competencies and an
   explanation. Prefer behavioural checks to scripts that compare YAML shape,
   so that every valid solution gets full credit.
4. Run =CKA_LABS_DIR=<drafts> cka dev validate= and
   =CKA_LABS_DIR=<drafts> cka dev verify <id>=, then move the directory into
   =labs/=.
